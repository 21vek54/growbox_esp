# 🌱 growbox_esp — Растишка

Прошивка умного гроубокса на **ESP32-S3** (PlatformIO + ESP-IDF): датчики, фитолампа по расписанию, MQTT и обновление по воздуху (ArduinoOTA / espota).

![Превью растения](docs/plant-preview.png)

## Возможности

- Температура и влажность воздуха (RS485)
- Влажность почвы (два датчика ADC)
- Реле через расширитель TCA9554; реле 1 — фитолампа по расписанию (время включения + длительность)
- Реле 2 — клапан автополива по влажности почвы: порции с паузой на впитывание, суточный лимит, контроль исправности датчиков
- Точное время по SNTP (UTC+7)
- HTTP только для чтения статуса (`/api/status`), без сайта и без управления реле
- OTA по Wi‑Fi: `pio run -e ota -t upload` (протокол ArduinoOTA / espota)
- MQTT на Mosquitto SZBOX: средняя телеметрия раз в минуту (`termo/home/rastishka/status`), команды и мгновенный снимок состояния

## Железо

| Параметр | Значение |

## Быстрый старт

```bash
# Первая прошивка — только USB (меняет таблицу разделов)
pio run -e esp32-s3-devkitc-1 -t upload

# Монитор — в логе будет IP
pio device monitor
```

Дальше по воздуху. В `platformio.ini` в секции `[env:ota]` укажите IP платы и тот же пароль, что `OTA_PASS` в `src/variables.h` (сейчас `rastishka-ota`):

```bash
pio run -e ota -t upload
```

Статус: `http://<IP>/api/status`

### MQTT (средние раз в минуту)

1. Скопируйте `src/secrets.h.example` → `src/secrets.h` и укажите пароль пользователя `esp` на брокере `192.168.1.92`.
2. После прошивки подписка:

```bash
mosquitto_sub -h 192.168.1.92 -u esp -P '...' -t "termo/home/rastishka/#" -v
```

Сообщения с retain, примерно раз в 60 с; в JSON есть `samples` (число усреднённых опросов за минуту), `reset_reason` (причина последнего старта) и `boot_count` (номер загрузки, хранится в NVS).

Время и лампа (в `status` и `snapshot`):

| Поле | Значение |
|------|----------|
| `time` | время прибора `2026-09-29T11:05:12+0700`, `null` — неизвестно |
| `time_status` | `synced` — получено по NTP, `rtc` — пережило перезагрузку, ждёт NTP, `none` — неизвестно |
| `light` | реле фитолампы сейчас: `1` / `0` |
| `light_mode` | `auto` — по расписанию, `on` / `off` — вручную |
| `light_on`, `light_duration_min` | время включения `HH:MM` и длительность в минутах |

Почва и полив (в `status` и `snapshot`; `moisture`, `moisture2` остались — проценты каждого датчика):

| Поле | Значение |
|------|----------|
| `soil` | итоговая влажность почвы, %; `null` — нет исправных датчиков |
| `soil_source` | `avg` — среднее двух, `wetter` — расходятся >20 %, взят более влажный, `s1` / `s2` — работает один, `none` |
| `soil1_raw`, `soil2_raw` | сырое значение ADC (медиана 7 чтений) |
| `soil1_ok`, `soil2_ok` | датчик исправен и участвует в расчёте |
| `soil1_fault`, `soil2_fault` | `range` — обрыв/замыкание, `noise` — вход «плавает», `stuck` — не реагирует на полив, `null` |
| `valve` | клапан (реле 2): `1` открыт |
| `water_mode` | `auto` / `off` |
| `water_state` | `idle`, `dosing` (порция), `soaking` (пауза на впитывание) |
| `water_cycle`, `water_left_s` | вид цикла (`auto`, `manual`, `test`) и секунд до конца этапа; только во время цикла |
| `water_start`, `water_target` | начать полив ниже, остановить при достижении, % |
| `water_dose_s`, `water_soak_min` | длительность порции, с, и паузы, мин |
| `water_max_doses`, `water_doses_today` | суточный лимит порций и сколько уже было |
| `water_last` | время последней порции или `null` |
| `water_fault` | `no_effect` — порции не подняли влажность (авария, полив заблокирован), `null` |

Топики:

| Топик | Кто пишет | Назначение |
|-------|-----------|------------|
| `termo/home/rastishka/status` | плата, раз в 60 с | средние за минуту + поля выше |
| `termo/home/rastishka/cmd` | сервер | `{"id":"x","cmd":"status"}`, `{"id":"x","light":{"mode":"auto","on":"07:00","duration_min":960}}`, `{"id":"x","water":{...}}` |
| `termo/home/rastishka/snapshot` | плата, retain | мгновенные значения; при команде (`req_id`, `ok`, `error`), событии, переключении лампы и подключении |
| `termo/home/rastishka/event` | плата, без retain, QoS 1 | события: `soil_fault`, `soil_ok`, `water_start`, `water_done`, `water_limit`, `water_fault` |

Команда `water` (все поля необязательны): `mode` `auto`/`off`, `start` 5..90, `target` 10..95 (больше `start`), `dose_s` 1..120, `soak_min` 1..240, `max_doses` 1..50, `now` — ручная порция (секунды, `0` — обычная), `stop`, `reset` — снять аварию и исключение датчиков.

### Фитолампа (реле 1)

Расписание хранится в NVS и пересчитывается раз в секунду, поэтому после перезагрузки лампа сразу в правильном состоянии. Окно может переходить через полночь. В режиме `auto` без реального времени (`time_status: none`) лампа выключена. По умолчанию после первой прошивки — `off`, 08:00, 12 ч. Настройка — через бота MAX в группе «Цветок» (сервер публикует в `cmd`).

### Автополив (реле 2, клапан нормально закрытый)

Датчик считается неисправным после 3 плохих опросов подряд (сырое значение вне 500..3500 или разброс серии >300) и возвращается после 3 хороших. Итоговая влажность — среднее двух исправных; если они расходятся больше чем на 20 %, берётся более влажный, чтобы не залить растение из-за сломанного «сухого» датчика.

В режиме `auto` при `soil` ниже `start` клапан открывается на `dose_s`, затем пауза `soak_min`, и так до `target`. Каждая порция считается в суточный лимит `max_doses` (хранится в NVS). После каждой паузы проверяется отклик: если влажность одного датчика выросла на 3 % и больше, а другого нет, второй помечается `stuck` и исключается, пока его показания не изменятся. Если за 3 порции не вырос ни один — авария `no_effect`, полив блокируется до `reset` (нет воды, клапан или датчики). Если датчики расходятся дольше часа, а более сухой уже ниже `start`, делается одна пробная порция (не чаще раза в 12 ч), чтобы выяснить, кто из них врёт.

Клапан открыт только во время порции и не дольше 120 с; после старта платы все реле выключены. По умолчанию полив выключен (`off`), 35 → 50 %, порция 20 с, пауза 20 мин, 6 порций в сутки.

### Сторожевой таймер и перезагрузки

Wi‑Fi переподключается бесконечно, пауза между попытками растёт от 2 до 60 с. Плата перезагружается сама, если:

| Событие | Порог | `reset_reason` |
|---------|-------|----------------|
| Задача опроса датчиков или главный цикл не отмечаются у Task WDT | 60 с | `task_wdt` |
| Нет IP-адреса Wi‑Fi | 10 мин | `wifi_lost` |
| Нет успешной отправки в MQTT | 15 мин | `no_publish` |

Остальные значения `reset_reason`: `poweron` (питание), `sw` (OTA или `esp_restart`), `panic`, `int_wdt`, `brownout` (просадка питания), `ext`, `other`.

## Структура

```
src/           — main, HTTP, Wi‑Fi, ArduinoOTA, MQTT, health (watchdog), time_sync (SNTP), light (фитолампа), soil (датчики почвы), water (полив)
lib/           — ADC, I2C, RS485, TCA9554
docs/          — превью UI
```

## HTTP API (только чтение)

| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/` | JSON: имя, версия, ota |
| `GET` | `/api/status` | JSON: температура, влажность, почва, реле, IP, версия |

Реле по HTTP не управляются — только прошивкой через TCA9554. `/api/status` опрашивает сервер для уведомления «прибор недоступен».
